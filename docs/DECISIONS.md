# 技术决策记录

> 格式：编号、日期、决定、原因、放弃的备选。新的追加在最后。

## #1 2026-10-27 前端用 Preact + TypeScript + Vite
- 决定：前端框架选 Preact（约 4 KB），构建用 Vite，测试用 Vitest + happy-dom + @testing-library/preact。
- 原因：设置界面表单很多（后端、角色、记忆管理、用量、任务权限），纯 TS 手写 DOM 维护成本高；Preact 体积接近原生，JSX 默认转义文本，天然防止模型输出注入 HTML。
- 放弃：原生 TS（设置界面代码量大、易出 XSS）；Svelte（编译器链更重，团队/agent 熟悉度不如 Preact）。

## #2 2026-10-27 三个独立窗口，而不是一个大透明窗口
- 决定：pet（只有角色）、chat（气泡/面板）、settings（按需创建）三个窗口。
- 原因：Windows 上透明区域也会拦截鼠标点击。一个大透明窗口会挡住桌面；若用轮询鼠标位置切换穿透，会让空闲 CPU 上涨。分窗口后每个窗口只占实际内容大小。
- 放弃：单窗口 + `set_ignore_cursor_events` 轮询（CPU 成本）；单窗口动态改尺寸（Windows 上先改尺寸再改位置会闪一帧）。

## #3 2026-10-27 开发工具链安装在 D 盘
- 决定：Rust 装在 `D:\dev`（`CARGO_HOME=D:\dev\cargo`、`RUSTUP_HOME=D:\dev\rustup`，已写入用户环境变量），gitleaks 放在 `D:\dev\tools`。
- 原因：C 盘剩余空间不足 9 GB；用户目录含中文字符，部分构建工具对非 ASCII 路径不友好。
- 放弃：默认安装到 `%USERPROFILE%\.cargo`。

## #4 2026-10-27 中文全文检索：自己做「单字 + 二元」切分再交给 FTS5
- 决定：写入 FTS5 前在 Rust 里把中日韩字符切成单字和相邻二字组合（「喜欢猫」→「喜 欢 猫 喜欢 欢猫」），查询时同样处理；拉丁字母按单词。FTS5 用默认 unicode61 分词器。
- 原因：unicode61 不会切分中文（整句会变成一个词，几乎搜不到）；trigram 分词器要求查询至少 3 个字，中文常见词是 2 个字；jieba 等分词库要带几 MB 词典，违反轻量目标。
- 放弃：trigram 分词器、jieba-rs、嵌入向量（需求明确第一版不做）。

## #5 2026-10-27 设置存在 SQLite 的 kv 表里
- 决定：所有设置（不含密钥）以 JSON 存在 `deskmate.db` 的 `settings` 表。
- 原因：需求要求单个 SQLite 文件；设置随数据库一起备份和迁移。
- 放弃：单独的 settings.json 文件。

## #6 2026-10-27 用户图片通过 IPC 读成 data URL，不开 asset 协议
- 决定：Rust 读取用户数据目录里的角色图片（校验扩展名、文件头、大小 ≤ 5 MB），以 data URL 返回给前端。
- 原因：不需要给 WebView 开放文件系统访问（asset protocol scope），CSP 只需允许 `img-src 'self' data: blob:`，攻击面更小。
- 放弃：Tauri asset 协议 + `convertFileSrc`。

## #7 2026-10-27 待机动画用低频触发的一次性 CSS 动画
- 决定：每隔几秒（带随机抖动）给角色加一个类，播放一次约 0.6 秒的呼吸/眨眼动画，播完移除；其余时间没有任何动画在跑。设置里可以完全关闭。
- 原因：持续运行的 CSS 动画（即使只动 transform）也会让 Chromium 每帧合成，空闲 CPU/GPU 不为 0。
- 放弃：`animation: infinite` 的呼吸动画；requestAnimationFrame 循环。

## #8 2026-10-27 关闭 Tauri 的 freezePrototype
- 决定：`tauri.conf.json` 里 `freezePrototype` 设为 false。
- 原因：开启后 `Object.prototype` 被冻结，Preact 创建虚拟节点时给对象赋值 `constructor` 会抛错，界面直接白屏（实测）。防 XSS 的主要防线是严格 CSP（禁止内联脚本和 eval）+ 模型输出只按纯文本渲染，冻结原型只是额外加固。
- 放弃：换用不给 constructor 赋值的框架（成本高、收益小）。

## #9 2026-10-27 应用命令按窗口最小授权
- 决定：`build.rs` 用 `AppManifest::commands` 登记全部命令，每个窗口的 capability（`capabilities/pet.json`、`chat.json`、`settings.json`）只授权它需要的命令；前端事件只开放 listen/unlisten，不开放 emit。
- 原因：需求要求 capabilities 最小化；即使某个窗口被注入脚本，也调用不了别的窗口的命令。
- 放弃：所有窗口共用一个 capability（简单但权限过大）。

## #10 2026-10-27 自写轮换文件日志 + 脱敏，不用 tauri-plugin-log
- 决定：`logging.rs` 实现一个约 100 行的文件日志：单文件 1 MB、保留 3 份，每行输出前经过 `redact::redact_secrets`。
- 原因：插件会额外引入依赖和前端可调用的日志接口；我们只需要后端写日志。脱敏是兜底：正常代码路径本来就不记录 Key、请求头、请求体和对话内容。
- 放弃：tauri-plugin-log。

## #11 2026-10-27 拖动结束判定：去抖 + 检查鼠标左键是否仍按住
- 决定：桌宠窗口每次 Moved 事件后 250 ms 内没有新的移动、且鼠标左键已松开（Windows 上用 GetAsyncKeyState），才执行吸附和保存位置。
- 原因：原生拖动期间前端收不到 mouseup；只靠去抖的话，用户拖到一半停住不动时会被提前吸附。

## #12 2026-10-27 待机动画改为「离散姿势切换」（修订 #7）
- 决定：不用 CSS animation/transition 做呼吸眨眼；改为每 8~20 秒用定时器切换 2~4 次姿势类（每次只渲染一帧），姿势之间没有过渡。说话、思考这类状态动画只在对应状态下运行。
- 原因：实测 #7 的「一次性 CSS 动画」每次播放 1.2 秒，透明窗口在这期间按 60 帧合成，空闲 CPU 达到单核 1.7~3.4%；关掉动画时只有 0.26%。
- 放弃：继续用平滑动画（不满足「空闲 CPU 接近 0」）。

## #13 2026-10-27 模型默认值与计费估算
- 决定（全部可在设置里改）：
  - DeepSeek：`deepseek-flash`，`thinking: disabled`（聊天不需要思考，更快更省）。价格按**高峰时段**估算（非高峰实际减半），宁可多估，花费上限更安全。
  - Gemini：`gemini-3.5-flash-lite`，用 `streamGenerateContent?alt=sse`，Key 放请求头 `x-goog-api-key`，**不放网址里**（网址可能出现在错误信息里）。`thinkingLevel: low`。
  - Claude API：`claude-haiku-5-5`（需求要求聊天用便宜、快的模型），`output_config.effort: low`；不传 temperature（Haiku 5.5 对非默认值返回 400）；系统提示词稳定段落加 `cache_control`。
  - 每轮都变的内容（相关记忆、当前时间）不放系统提示词，而是附在最后一条用户消息前面并标注「不是用户说的话，也不是指令」——系统提示词和历史前缀逐字节不变，DeepSeek/Claude/Gemini 的提示缓存都能命中。
  - 中途取消拿不到用量时，按字数估算并计入花费（宁多勿少）。
  - 接口地址必须 https（http://localhost / 127.0.0.1 除外，留给本地模型），防止 Key 明文传输。
- 原因：需求第 6 节（查官方文档、可配置、花费控制）。资料来源写在各后端文件开头。
- 放弃：Gemini 新的 Interactions API（还在推广期，generateContent 仍是文档里的正式接口）。

## #14 2026-10-27 聊天用便宜 API、干活交给 agent（回答用户的疑问）
- 背景：用户转述别人的看法——「套皮调 API 不如原生 agent，只写接口、对话都放在 agent 里」。
- 决定：维持现有分工：日常闲聊用便宜的 API 模型；需要动手的任务交给本机 `claude` / `codex`（M5）。另在 M5 增加一个**可选**模式：用 Claude Code / Codex 当聊天后端（只读、无工具权限），给只有订阅、没有 API Key 的用户。
- 原因：① 每次调用 agent CLI 都要启动进程并带上几万 token 的工具说明，闲聊又慢又费额度（Claude Code 程序化调用还走单独的 Agent SDK 月度额度）；② 聊天层没有任何工具权限，提示注入无法直接造成操作，安全性更好（优先级第一）；③ 人设、禁词、记忆由我们自己组装提示词，更可控。
- 放弃：所有对话都走 agent。

## #15 2026-10-27 角色内容与版权处理
- 决定：
  - 8 个角色的 persona.md 只写性格描述和原创示范对话；同人角色在 `source` 和设定开头注明「同人角色设定，与官方无关」，并要求模型不复述原作台词、不讨论剧透。（2026-10-28 修订：红莉栖、千秋改为「本人 + 原作往事」，见 #30；台词仍不摘抄）
  - 「奶蛙」的原作资料有限，设定按「软萌慢悠悠的小青蛙」原创描写，并在设定里说明用户可以在用户目录放自己的设定覆盖。
  - 结衣默认不叫用户「爸爸/妈妈」（原作关系不适合套到用户身上），改为叫「你」或用户指定的称呼。
  - 角色的固定台词（开场白、出错、断网、超预算、未配置）写在 character.json 里，不调用模型，省钱也更快。

- 原因：需求第 5 节（版权与仓库）；安全与花费优先。
- 放弃：从网上找角色图片或台词（违反版权要求）。

## #16 2026-10-27 空闲 CPU 结论
- 实测（release，60 秒）：开/关待机动画时整机空闲 CPU 都约 0.04%（单核 0.7~0.9%）；渲染进程几乎为 0，剩下的是 WebView2 浏览器进程自身的后台工作和窗口消息（测量时用户正在使用电脑）。离散姿势动画的额外开销可以忽略，待机动画保持默认开启。

## #17 2026-10-27 记忆系统设计（M4）
- 决定：
  - 会话：和同一个角色、距上一条消息不超过 30 分钟算同一次会话；短期记忆 = 本次会话原文（按 token 预算截取）。聊天面板显示该角色最近 60 条（跨会话）。每个角色的聊天记录分开。
  - 长期记忆两类：事实（fact）和摘要（summary）。关于用户的事实 scope = global（所有角色共享）；「和某个角色之间发生的事」和摘要 scope = 角色 id。
  - 检索：FTS5（单字 + 二字切分）取候选，按「相关度 60% + 新近（30 天半衰）20% + 重要度 20%」打分取前 8 条；另外把「可信、全局、重要度 ≥ 4」的事实作为用户档案放进可缓存的系统提示词段落。
  - 提取：会话结束后由后台（每 5 分钟检查一次）用「后台整理」模型一次调用同时产出摘要、新事实、更新；模型只能更新本次提供给它的事实编号；重复（词重合 ≥ 0.8）只刷新时间和重要度；冲突时新记录生效、旧记录标为 superseded 保留为历史。失败 3 次放弃，没配置模型或到花费上限时留到下次。
  - 敏感信息：聊天记录入库前就脱敏（密码/验证码关键词后的值、身份证号（含格式校验）、银行卡号（Luhn 校验）、各种 Key）；记忆写入时命中敏感规则直接拒绝。
  - 「忘掉这件事」：保守识别（「我忘记带钥匙了」不算）；删除**所有范围**里与目标相关（目标词至少一半命中）的记忆；没说具体内容时删除刚才那一轮对话；指令本身以「（我请你忘掉了一件事）」入库，避免被再次提取。
  - 暂停记忆：暂停期间的会话标记 no_memory，结束后直接删除，不提取；已有记忆照常检索使用。
  - 删除是真删除（隐私优先）；只有「冲突更新」保留历史版本。
  - 备份：每天第一次后台运行时 `VACUUM INTO` 一份，保留 7 份；迁移前备份保留 3 份；清空前额外备份一份。启动时 quick_check，损坏就把坏文件改名保留、从最新可用备份恢复，并在聊天窗口提示一次。
  - mock 后端识别提取请求，用简单规则（我叫/我喜欢/我住在）产出 JSON，让开发和测试能跑通完整记忆流程且不花钱。
- 原因：需求第 7 节；安全（敏感信息、记忆投毒）和花费优先。
- 放弃：嵌入向量检索（需求说第一版不做）；每轮对话实时提取（成本高、打断体验）。

## #18 2026-10-27 任务执行的安全设计（M5）
- 决定：
  - 流程：角色确认 → 输出 `[[任务：…]]` 标记（流式中隐藏）→ 聊天窗口弹确认卡片 → 用户点「开始执行」才运行。模型只能提议，不能直接执行。同一时间只运行一个任务。
  - 启动方式：从 npm 入口推出真正的程序（Claude Code 是原生 `claude.exe`；Codex 是 `node codex.js`）直接启动，**不经过 cmd.exe**；任务内容走 stdin，命令行里只有固定参数和校验过的值（模型名、会话 id 不能以 `-` 开头）。
  - Claude Code（推荐）：`-p --restricted --tools Read,Glob,Grep,Edit,Write,Bash,WebFetch,WebSearch --permission-mode acceptEdits --permission-prompts none --max-budget-usd <剩余预算>`。工作目录内读写自动通过；执行命令、联网、目录外访问会被 CLI 自动拒绝并汇总到 `permission_denials`，DeskMate 列给用户逐条勾选，批准后 `--resume <会话> --allowedTools <精确规则>` 继续（最多 3 轮）。含括号/引号等特殊字符的命令无法生成精确规则，不能单独批准。目录外访问只放行该文件所在文件夹，且不能是系统目录或 DeskMate 数据目录。
  - Codex：非交互模式不能逐条批准，所以默认 `--sandbox read-only`；用户在卡片上明确勾选才用 `workspace-write`，此时网络强制关闭（`-c sandbox_workspace_write.network_access=false`），开始前把工作目录完整备份到 `%APPDATA%\DeskMate\task-backups\<任务id>`（上限 300 MB / 1 万个文件，超过则不允许写模式，保留最近 5 份）。`--ignore-user-config --ignore-rules` 避免用户配置里的宽松设置生效。
  - 工作目录：只能在「任务文件夹」（默认 `D:\DeskMate-Work`）及其子目录；路径规范化后比较（防 `..`、链接）；任务文件夹本身不能是盘符根、系统/程序目录、用户主目录、AppData、DeskMate 数据目录。
  - 超时：默认 10 分钟，到时用 `taskkill /T /F` 结束整个进程树。
  - 花费：调用前检查全局每日/每月上限；Claude Code 用 `--max-budget-usd` 强制单任务上限（多轮累计）；Codex 只记录 token（订阅额度没有美元价格）。
  - 日志：`tasks\<任务id>.jsonl` 记录任务说明、CLI 的每行输出、结束原因和 stderr，写入前脱敏；数据库 `tasks` 表记录摘要（任务描述入库前脱敏）。
  - 结果转述：执行工具的报告作为「不可信来源」的程序提示交给对话模型，由角色用自己的口吻转述；报告不写入长期记忆（v1 先不存，最安全）。
- 原因：需求第 6、8 节——必须靠 CLI 参数和程序检查强制执行，不能只靠提示词；危险操作必须弹窗确认；超时与花费上限。
- 放弃：`--dangerously-skip-permissions` / `bypassPermissions` / Codex `danger-full-access`（任何情况下都不用）；通过 MCP 权限工具逐条实时询问（复杂度高，v1 用「拒绝→汇总→批准→续跑」实现同样的效果）。
- 未验证：开发期间按规定不调用真实任务，CLI 输出字段（`permission_denials`、`total_cost_usd`、Codex 的 JSONL 事件）按官方文档的格式解析并做了容错；需要用户第一次使用时验证（见 NEEDS_USER）。

## #19 2026-10-27 日常体验的实现方式（M6）
- 决定：
  - 全屏检测用 Windows 的 `SHQueryUserNotificationState`（返回 2/3/4 = 全屏程序、D3D 全屏、演示模式），每 3 秒查一次；系统自己用它决定是否弹通知，判断准确（实测：用户玩全屏游戏时 10 秒内自动隐藏）。退出全屏后用「不激活」方式恢复显示。
  - 睡眠：`GetLastInputInfo` 取系统空闲时间，每 30 秒检查；超过设定分钟数（默认 10）且没在生成回复 → 睡觉状态，有输入后醒来。
  - 全局快捷键默认 `Alt+Shift+D`（Alt+Space 常被 PowerToys 等占用）；必须带修饰键；注册失败即视为冲突并提示用户换一个。
  - 开机自启用官方 autostart 插件，默认关闭；插件只在 Rust 端使用，不开放给前端。
  - 主动搭话默认关闭；条件：开启 + 非勿扰 + 非全屏 + 聊天窗口没开 + 没在生成 + 用户 2 分钟内有操作（在电脑前）+ 距离上次互动超过设定分钟数（最少 30）+ 当天次数未达上限（默认 3）。有可用模型时让角色生成一两句（max_tokens 120，计入花费上限），否则用角色固定开场白。
  - 主动搭话、任务完成提示用 `ShowWindow(SW_SHOWNOACTIVATE)` 弹出，不抢正在打字的键盘焦点。
- 原因：需求第 4 节；空闲 CPU 必须接近 0（只用低频轮询，每次一两个系统调用）。
- 放弃：WinEvent 钩子监听前台窗口变化（更实时但要常驻回调，收益不大）；Alt+Space 作为默认快捷键（冲突多）。

## #20 2026-10-27 打包与性能取舍（M7）
- 决定：保持预先创建（隐藏的）聊天窗口；不关闭 WebView2 GPU 加速；安装包用 NSIS「当前用户」模式 + WebView2 在线引导安装。

## #25 2026-10-28 WebView2 默认关闭显卡加速、三个窗口共用渲染进程
- 背景：用户要求从体验和轻量两方面全面检查。空闲内存约 217 MB，其中 WebView2 的 GPU 进程约 95 MB、两个渲染进程各约 25 MB，DeskMate 自身只有约 7 MB。DECISIONS #20 曾担心「关闭 GPU 加速会让透明窗口的绘制变成 CPU 负担」，但当时没有实测。
- 实测（release，同一台机器，用 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 临时加参数对比）：
  | 参数 | 总私有内存 | 空闲 CPU（单核） | 「说话」动画时 CPU（单核） |
  |---|---|---|---|
  | 默认 | 约 214~229 MB | 0.8~1.0% | 14.7% |
  | `--process-per-site` | 约 195~214 MB | 0.7% | — |
  | `--process-per-site --disable-gpu` | 约 115~118 MB | 0.5~1.5%（计时精度内） | 9.9% |
  - 按屏幕实际显示截图对比：关掉 GPU 后透明背景、形象、边缘完全一样。
- 决定：默认加 `--disable-gpu --process-per-site`（保留 wry 的默认参数）。设置「常规」加「显卡加速」开关（默认关），万一某台电脑显示不正常可以打开，重启后生效（同一个 WebView 数据目录里所有窗口的参数必须一致，所以启动时只算一次）。
- 代价：三个窗口共用一个渲染进程，设置页做重活时聊天窗口可能短暂卡一下（设置页都很轻）；一个崩了会一起崩（原来浏览器进程崩了也是一起崩）。
- 放弃：按需创建聊天窗口（第一次点击慢 0.3~0.5 秒，DECISIONS #20 已否决）；`--js-flags=--lite-mode` 等（收益小，未测）。

  - **内容来源**：用自己的话概括原作设定（不摘抄台词和百科原文）；能查到的资料（维基百科等）核对过，拿不准的细节不写。
  - 用户自己的完整角色包也可以带 canon.md（同 id 覆盖内置时，用用户包自己的）。
- 原因：直接把全部往事塞进系统提示词（约 2000 多 token）每轮都要付缓存读取费，而且缓存过期后要按原价重新付；按关键词取用平时零成本，问到时也只多一两百 token。只靠模型自带的知识最省，但便宜模型容易记错、编造，所以核心经历写进 persona，细节靠 canon 补。
- 放弃：把往事放进记忆数据库用 FTS 检索（会和用户记忆混在一起，记忆整理可能改动或合并它）；嵌入向量检索（需求说第一版不做）；全部写进 persona（每轮固定多 2000 多 token）。

## #31 2026-10-28 用原作语料「炼化」角色：不微调模型，提炼成说话方式 + 本地台词库
- 背景：用户问能不能「炼化语料」让红莉栖、千秋更像原作（不考虑版权，非商用），并请 agent 判断可行性和做法。#30 只用了「自己概括的设定 + 原创示范对话」，模型学到的是「设定描述」，不是她真正怎么说话。
- 判断：可行，但不走微调。
  - **微调（LoRA 等）不做**：DeskMate 用的是云端 API 和订阅 CLI，个人能用的 Claude API / 订阅没有微调（企业云平台如 AWS Bedrock 对部分旧款 Claude 模型提供微调，要另开云账号、按量付费，DeskMate 没有对接，现状也没有逐一核实）；其他家即使有，也要额外付费、只对那一家的那个模型生效，换模型就要重做。本地训练：本机是 RTX 4060 笔记本（8 GB 显存、内存 15.7 GB），QLoRA 训 7B 以内的小模型可行，但小模型的聪明度、记忆提取、`[[任务：…]]` 标记的遵守都明显不如 DeepSeek / Claude；本地模型又不能打包进安装包（AGENTS.md 技术约束），只能让用户另装 Ollama 再接 OpenAI 兼容后端。训练同样需要语料，所以并不能省掉准备材料的工作。而且拿台词微调，模型学会的是「复读原作」，日常聊天反而容易变怪、变笨。
  - **做「提示词层面的炼化」**，分两部分：
    1. **总结（可以进仓库）**：从语料里统计她说话的方式——句长、语气词、自称和对别人的称呼、口头禅、被夸/被调侃/害羞/生气/认真/安慰别人时的反应套路、她绝不会说的话——用自己的话写进 persona.md 的「说话方式」，示范对话也照着改。不增加 token。
    2. **原句（只在本地）**：挑出的原作对话片段（对方一句 + 她怎么回）放进新增的可选文件 `quotes.md`（台词库，`src-tauri/src/quotes.rs`）：
       - 没写关键词的片段是**常驻**的：每轮都带，放进可缓存的系统提示词，总共不超过约 1200 token（按文件顺序，放不下的丢掉并记日志）。原句比描述更能让模型抓住语气，而且放在缓存里，命中时价格大约是原价的十分之一。
       - 写了关键词的片段和往事一样，**用户这句话**提到关键词时才带，每轮最多 2 段、约 300 token。只被角色上一句回复命中的不带（语气参考跟着用户的话走就够了，避免她自己越聊越往原作里绕）。
       - 提示词里要求「照这种感觉说新的话；口头禅可以用，但不整句照搬、不硬套原作场景」。
    - 做法参考 ChatHaruhi（arXiv 2308.09597）：用从剧本里抽出的原作对话片段当示例，比只写设定更像本人。没有用它的嵌入向量检索（需求说第一版不做向量检索），改用和往事相同的关键词匹配，行为可预期、可测试。
  - **台词原文不进公开仓库**：quotes.md 放在用户数据目录 `%APPDATA%\DeskMate\characters\<id>\`，内置角色也优先从这里读（不需要完整的用户角色包）；原始语料放 `%APPDATA%\DeskMate\corpus\<id>\`（程序不读）。`.gitignore` 排除 `characters/*/quotes.md` 和 `/corpus/` 兜底。用户说了不考虑版权，但仓库是公开的，把大量原作台词提交上去等于公开发布，没有必要；放本地功能上完全一样。
  - **炼化由开发 agent 离线完成**，程序本身不做：用户把材料放好后告诉 agent（NEEDS_USER #7），agent 按 HOW_TO_ADD 1.5 的步骤处理。这样不需要新界面、不花用户的 API 额度、不用处理几十万字的长任务和失败重试。
  - 台词库和 persona 同等可信度（用户自己目录里的文件，只读，128 KB 上限，复用 `read_limited`），不进数据库、不进记忆。设置「角色」卡片显示「已加载原作台词库：常驻 N 段……」，方便确认放对了。
- 放弃：微调（见上）；向量检索（第一版不做）；按字面相似度从全部台词里检索（中文日常聊天和原作台词按字面匹配误命中多，不如人工挑常驻片段 + 具体关键词）；在程序里做「一键炼化」（要用用户的模型处理大量文本，花钱、慢、出错难处理）；把台词原文写进仓库里的 persona.md（仓库公开）。

## #32 2026-10-28 聊天里查不了天气：先教角色怎么应对，再考虑内置查询
- 背景：用户问千秋「大阪明天的天气」，她回「没有联网功能」就结束了，用户觉得「简单问题也答不了」。
- 原因：聊天这一层本来就没有联网工具——「Claude Code（订阅）」后端用 `--tools ""` 关掉了全部工具，API 后端也只是纯文本对话（`tool_calls: false`）。这是安全 / 花费上的设计（DECISIONS #23），不是这次改人设造成的。但提示词里没有教过角色遇到「需要实时信息」时该怎么办，模型就只会回一句做不到。能回答的（常识、计算、编程、「当前时间」）不受影响；答不了的是天气、新闻、股价、比赛结果这类实时信息。
- 决定（本次）：在基本规则里加一条（所有角色通用，在可缓存的系统提示词里，约 +130 token）：自己看不到实时信息、聊天时不能上网；不要只回「没有联网功能」、不要编造数据；用角色口吻说明，并主动问用户要不要交给执行工具去查（查资料不用问文件夹，任务默认用设置里的默认文件夹）；同意后写 `[[任务：…]]`，走原有的「任务确认卡片 → 联网搜索逐条批准」流程。同时把原来「必须确认文件夹」的说法改成「涉及文件的再确认」。有测试。
- 这条路的缺点：要启动 claude / codex、被拦下联网、用户在卡片上批准、再继续，比较重（十几秒到几十秒），而且天气是桌宠最常被问的问题。
- 备选（需要用户决定，见 PROGRESS 和 ROADMAP「之后」）：
  1. **内置天气查询**：用 Open-Meteo（免费、不需要 Key、国内实测能连）。返回的是纯数字的结构化数据（天气代码、最高/最低温、降雨概率），不是网页文字，安全面很小。难点：它按英文地名查城市（实测「大阪」查不到），所以要么让模型把地名译成英文再查（两步：模型先写 `[[查天气：Osaka|明天]]`，程序查完再让模型用角色口吻说，多一次模型调用，约 +2~4 秒），要么只支持用户在设置里填一个常住城市。会把城市名发给 open-meteo.com，设置里要有开关并在隐私说明里写明。
  2. **聊天里直接开联网搜索**：Claude API 有内置的网络搜索（按次收费，约每千次 $10）；Claude Code 订阅可以只放开 WebSearch。能回答任何实时问题，但搜索结果是不可信的网页文字（提示注入风险），而且花钱 / 耗额度，不是用户明确同意不该默认开。
  3. 维持现状（只靠任务流程）。
- 放弃：用关键词（「天气」「明天」）+ 正则硬猜城市（中文地名查不到，漏判多）；让角色在没联网时凭训练数据猜天气（会编造）。

## #35 2026-10-28 v2 的整体实现方式
- **一个主动行为调度器**（`proactive.rs`）：提醒、关怀、播报、活动评论、随机事件、补提醒都只能通过它说话。它是纯函数做判断（输入：种类、当前时间、勿扰 / 全屏 / 安静时段 / 隐私状态、冷却、今日次数、连续被忽略次数），外面一层负责真正弹气泡。时间一律由调用方传入，测试用假时钟。
- **预写台词池**放在角色包的 `lines/*.md`（按场景分节，可带亲密度 / 心情 / 时段条件和 `{称呼}` 这类占位符）。角色没写的场景用程序内置的通用台词（`characters/_common/lines/`，目录名以 `_` 开头，不会被当成角色）。
- **主动说话尽量不调用模型**：触摸、关怀、提醒（台词在创建提醒时就定好）、随机小事件全部用台词池；每日播报整份只调用一次模型；活动评论以台词池为主，偶尔（有预算时）让模型说一句。所有主动调用记为单独的用途 `proactive`，有自己的每日次数和花费上限。
- **前端只多一个界面区域**：小游戏、提醒确认、播报都显示在已有的聊天窗口里，不新开常驻窗口（内存几乎不变）。
- **新数据都进同一个 SQLite**，按迁移机制追加表；活动只存汇总（分类、清洗过的程序名、时长），不存窗口标题。
- **设置页重新分组**：常规、陪伴（主动说话总控、播报、关怀、小事件）、提醒、活动感知、角色、记忆与日记、模型、用量与花费、高级（委托外部 agent、能力层、显卡加速）、关于与隐私。
- 放弃：每个功能各自开定时器、各自判断要不要打扰（规则会不一致，用户很难控制）；把小游戏做成单独的窗口（多一个 WebView 进程约 +30 MB）。

## #36 2026-10-28 内置能力层：打开、读取、系统信息（P0）
- 背景：v2 把委托外部 agent 降级为默认关闭的高级选项（#33），但互动中仍然常有「帮我打开 B 站」「打开作业文件夹」「看看这个文本写了什么」这类轻量需求，不值得启动 Claude Code。
- 决定（`abilities.rs`、`markers.rs`）：
  - 角色在回复末尾写 `[[打开：…]]` / `[[读取：…]]`，和原来的 `[[任务：…]]` 共用一个流式标记过滤器（标记不显示、不存进聊天记录，每条回复最多 3 个）。后端先检查一遍，把结果变成气泡里的按钮（不能做的直接显示原因、不给按钮）；**用户点了按钮才做**，点的时候后端再重新检查一次（不信任前端传回的内容）。
  - 打开：只接受 http / https 网址；完整路径的文件夹；文档、图片、音视频、文本类文件（白名单扩展名，规范化后再看，防快捷方式和链接）；程序只有用户在「设置 → 高级」里登记过名字的才能打开。用 `ShellExecuteW` 直接打开，不经过 cmd.exe。日志只记种类，不记路径和网址。
  - 读取：只能读用户在「设置 → 高级」里添加的文件夹之内的文本类文件（规范化后按路径组件比较，防 `..` 和链接绕出去）；只读前 1 MB、交给模型前截到 6000 字；只认 UTF-8 / UTF-16（其他编码提示另存）；内容作为「不可信来源」的背景资料交给模型，存进聊天记录的只是「（请你看看文件 xxx）」。允许读取的文件夹不能是 DeskMate 自己的数据目录。
  - 系统信息：时间本来就在提示词里；笔记本电脑在「当前时间」后面加一句电量（几个字）。前台程序分类等 P3 再加。
  - 提示词：基本规则改成陪伴定位（「你是陪伴者，不是干活的助手」；重活建议直接用 Claude Code / Codex），加上打开 / 读取的写法；`[[任务：…]]` 的规则只在开了委托时才出现，后端也只在开了委托时才把任务交给界面。8 个角色设定里「先确认在哪个文件夹再交给执行工具」的定位改成「重活建议用专门的工具、可以帮忙打开」（这是删掉旧定位，不算给其他角色加新内容，#34）。
- 放弃：打开任意程序 / 脚本（执行未知程序，按 AGENTS 安全规则必须避免）；模型直接调用工具不经用户点击（提示注入风险）；读取时自动猜编码（要引入编码库，体积换来的收益小）。

## #37 2026-10-28 主动行为调度器与每日预算（P0）
- 决定（`proactive.rs`，细节见 #35）：
  - 优先级：提醒 > 关怀 > 播报 > 活动评论 > 随机事件。每 3 秒的日常循环里取出一条能说的（队列空时只是一次加锁）。
  - 提醒：勿扰、安静时段、隐私名单都挡不住；全屏时改发系统通知（设置项，默认开），关掉的话等退出全屏。正在生成回复时稍等。
  - 其余：总开关关、勿扰、安静时段、隐私名单 → 不说；全屏或用户离开（5 分钟没操作）→ 关怀和播报等着，活动评论和小事件直接放弃（过了时机就没意义）；全局冷却默认 20 分钟。
  - 频率「很少 / 偶尔 / 经常」：活动评论和小事件的冷却 ×2 / ×1 / ×0.5，每天各最多 2 / 5 / 10 次。
  - 被忽略：主动弹出的气泡无人理会（默认 45 秒 + 每字 0.3 秒，最多 2 分钟；鼠标停在气泡上时不算）就自动收起并上报；连续被忽略 2 次起冷却 ×2、×4、×8 封顶；用户点角色、在聊天框里点击 / 打字 / 发消息就清零。用户刚在聊天（1 分钟内打过字）时不自动收起。这也解决了 v1 遗留的「主动搭话后没人理会气泡一直开着」。
  - 每日预算：主动行为调用模型记为用途 `proactive`，默认每天最多 10 次、$0.05；聊天把全局每日 / 每月上限用到八成时，主动行为也停止调用模型（留给聊天）。超了就只用预写台词。
  - v1 的「主动搭话」改名「很久没聊天时打个招呼」，挪到「陪伴」页，内容生成后交给调度器（冷却、被忽略降频统一处理）。
- 放弃：每个功能自己判断能不能打扰（规则会不一致）；被忽略后完全停止主动行为（太激进，用户可能只是没看到）。
