## 1. 新定位

一个住在桌面角落、像真人一样陪着用户的角色。她会在开机时跟你打招呼、告诉你天气和今天的事；会注意到你在打游戏、写代码、看视频，偶尔说上一句；能陪你玩小游戏、互动、聊天；会记得你托付给她的提醒。

**重点是互动过程本身，不是帮用户完成工作。**

优先级（冲突时按此顺序取舍）：
1. 安全与隐私
2. 不打扰：主动行为必须克制、可控、可关闭
3. 互动体验与角色感（像一个有性格的人，而不是通知弹窗）
4. 轻量与低成本
5. 功能数量

## 2. 核心设计原则

- **规则在本地，模型只负责说话。** 判断「现在该不该说话、该说什么类型的话」全部由本地代码完成；只在需要生成角色台词时才调用模型。
- **事件驱动，不轮询模型。** 只在状态变化（切换程序、到了提醒时间、游戏出现关键局面）时才考虑调用模型，并有冷却时间。
- **能不调用就不调用。** 每个角色包自带预写台词池（见第 7 节），常见场景直接从台词池里随机选；只有需要结合具体上下文时才调用模型。
- **离线也能用。** 没有网络、没有配置 Key、或今日额度用完时，桌宠仍然能显示、互动、玩本地小游戏、触发提醒，只是改用预写台词。
- **每日调用预算。** 设置里有「每日主动调用次数上限」和花费上限；主动行为（播报、活动评论）和用户发起的对话分开计数，主动行为先被限制。
- **隐私默认保守。** 所有感知类功能默认只用最低一层（见第 4.2 节），截屏默认关闭。

## 3. 降级 v1 的 agent 功能

agent 能力不再是卖点，但不能完全删掉：互动中仍可能需要打开文件、打开网页、执行简单操作。

### 改动
- 主界面和右键菜单中移除「执行任务」这类入口；设置里的相关配置移到「高级」分区。
- 角色设定和系统提示词里删掉「我可以帮你写代码/完成任务」之类的自我定位；角色不主动提出帮用户干活。
- 用户在对话中要求写代码、改代码这类重度任务时：角色用自己的口吻回应，建议用户直接用 Claude Code 或 Codex。如果用户在高级设置里开启了「允许委托外部 agent」，可以在确认后委托，否则不委托。

### 保留为「能力层」
把 agent 相关代码重构为一组轻量的内置能力，供互动功能调用：
- 打开指定文件夹、文件、网址或程序（打开前在气泡里告诉用户要打开什么）
- 在用户指定的目录内读取文件内容（比如「帮我看看这个文本写了什么」）
- 查询系统信息（时间、电量、当前前台程序等）

这些内置能力优先于外部 agent。Claude Code / Codex 命令行委托作为高级选项保留，**默认关闭**。

### 注意
- 原有的安全限制（工作目录限制、危险操作确认、超时、花费上限、任务日志）全部保留，不能因为降级而放松。
- 降级的模块改为**按需加载**，不在启动时初始化，降低空闲内存。
- 确认确实不再使用的代码才删除，删除前在 DECISIONS 里记录。

## 4. 新功能

### 4.1 每日播报与日常仪式

**触发**：每天第一次开机/启动时（可关闭）；以及用户自定义的时间点（比如早上 8 点、晚上 11 点的「睡前问候」）。

**内容模块**（每个模块可单独开关，每次随机挑选组合和顺序，避免每天一模一样）：
- 天气与气温，以及据此给出的建议（带伞、加衣服、适合出门等）
- 今天是否节假日、周末；节假日时推荐适合去玩的类型
- 吃饭建议（按时间、天气、季节和记忆中用户的口味）
- 新闻摘要（来自用户配置的 RSS 源，挑 2~3 条用角色口吻简述）
- 今天的提醒事项
- 特殊日期：用户生日、纪念日、节日、角色自己的生日
- 昨天的日记里留下的话题（见 4.4）

**数据来源要求**：
- 天气优先使用无需 Key 的免费接口；接入前查阅官方文档确认用法和使用条款。
- 节假日：用小体积的本地数据或轻量库，按用户所在国家/地区（设置项）判断，支持多国。
- 用户所在城市由用户在设置里填写，只存在本地用户数据目录；**代码、示例配置、测试数据、文档里不能出现任何真实的个人位置信息**。
- 吃饭推荐只推荐菜式和类型，**不要让模型编造具体的店名和地址**。如果以后接入地图服务，另作为可选功能。
- 新闻只用用户配置的源；默认提供几个示例源但默认关闭。
- 所有外部数据请求失败时安静降级（跳过该模块），不弹错误。

**成本**：所有数据先在本地拼好，整份播报只调用一次模型生成角色台词；模型不可用时用模板 + 预写台词拼出来。

### 4.2 活动感知（最难，分层实现）

**第一层（默认开启，零成本）**：读取前台窗口的进程名和窗口标题，本地规则分类：
- 游戏（Steam/Epic 等平台进程、用户添加的游戏程序）
- 写代码（常见编辑器和 IDE）
- 写作/作业（文档、笔记类软件）
- 看视频、听音乐（播放器、视频网站标题关键词）
- 浏览、聊天、会议等
- 空闲（长时间无键鼠操作）

前台窗口切换用系统事件监听（如 Windows 的前台窗口变更事件），不要高频轮询。

**第二层（默认开启，低成本）**：根据第一层的状态变化决定是否说话，比如：
- 刚开始玩某个游戏、玩了很久、凌晨还在玩
- 写代码写了很久、刚从写作业切到视频
- 每次决定说话前检查冷却时间、勿扰、全屏、每日预算
- 发给模型的只有「分类 + 持续时长 + 经过清洗的程序名」，**不发送原始窗口标题**（标题里可能有私人信息，比如文件名、聊天对象、网页标题）。

**第三层（默认关闭，有成本）**：截屏 + 视觉模型，理解具体画面（比如「这局打得怎么样」）。
- 只在两种情况下使用：用户按快捷键主动让她「看一眼」；或用户对某个具体游戏单独开启了「允许偶尔看画面」，并设置频率上限。
- 截图只在内存中处理，发送后立即丢弃，**不写入硬盘，不写入记忆**。
- 设置里显示第三层的累计花费。

**用户规则**（设置里一个清晰的列表界面）：
- 按程序或分类设置：可以评论 / 保持安静 / 回避（角色转过身或暂时隐藏）
- 全局评论频率（很少 / 偶尔 / 经常）、安静时段
- 隐私名单：密码管理器、网银、浏览器隐身窗口等默认处于「回避」状态，在这些程序前台时完全不记录、不评论

**记录**：只把汇总写进活动日志（如「今晚玩了 2 小时某游戏」），用于日记和关怀提醒，不记录原始标题。

### 4.3 小游戏

**框架**：小游戏做成和角色包类似的独立模块，新增游戏不改核心代码。游戏规则、胜负判定全部本地实现；角色只在关键时刻（开局、领先、落后、获胜、失败、平局）说话。

**角色反应**：不同角色对同一事件的反应不同（比如有的输了会不服气，有的会认真分析）。常见反应优先从预写台词池取，偶尔调用模型生成新台词增加变化。

**初始游戏**（按顺序做，先做纯本地的）：
1. 猜拳
2. 井字棋（角色有难度设定，不能总是赢或总是输）
3. 21 点
4. 每日运势/抽签（纯本地随机 + 角色口吻解读）
5. 成语接龙（需要模型或小体积词库，注意体积）
6. 海龟汤（模型当主持人，谜题必须原创，不能照搬网上现成题目）
7. 二十问（角色想一个东西，用户来猜）

**记录**：胜负战绩保存在本地；游戏结果会影响角色心情和亲密度（见 4.4）。

### 4.4 角色感与互动（类似 galgame 的体验）

- **触摸互动**：点击头部、身体、拖动、长时间不理她，都有不同反应和表情。
- **心情状态**：角色有简单的心情值，受互动、游戏结果、天气、时间段影响，体现在表情和说话语气上；心情会随时间自然回到平常状态。
- **亲密度**：随日常互动缓慢增长，解锁新的称呼、新台词、新话题。
- **随机小事件**：偶尔分享「她今天做了什么」、提一个问题、给一个选项让用户选，选择会影响回应。
- **桌宠日记**：每天结束时，根据当天的活动汇总、对话、游戏、提醒，以角色第一人称写一篇短日记。用户可以在界面里翻看；日记同时作为记忆系统的素材。每天只生成一次。
- **特殊日期**：记住用户告诉她的生日、纪念日，当天有特别的问候。
- **随天气和季节换表情或装扮**（只是切换图片，零成本；用户图片缺少对应状态时回退到默认图）。

**健康边界（必须遵守）**：
- 不制造愧疚感：用户很久没来时，可以表达想念，但不能指责、哭诉、让用户觉得有义务回来。
- 亲密度不会因为用户离开而下降，没有惩罚机制。
- 不阻止用户关闭、隐藏程序，不劝用户少和别人来往。
- 关怀提醒（休息、熬夜）是温和建议，用户可以关闭。

### 4.5 提醒与日程

- 用户用自然语言吩咐，比如「半小时后提醒我收衣服」「明天开机时提醒我交作业」「每周五晚上提醒我倒垃圾」「下次我开始打游戏的时候提醒我先写作业」。
- 只在吩咐的那一刻调用一次模型，把这句话解析成结构化提醒：触发方式（某个时间点 / 下次开机 / 某天开机 / 进入某种活动状态时）、重复规则、内容。解析结果用一句话复述给用户确认。解析失败时让用户换个说法，或提供简单的手动表单。
- 创建时就生成好到时候要说的角色台词并保存，触发时不再调用模型。
- 本地定时器触发；电脑关机期间错过的提醒，在下次开机时补提醒并说明是错过的。
- 提醒列表界面：查看、编辑、删除、暂停。
- 重要提醒可同时发系统通知（设置项）。
- 不涉及模型的部分必须在完全离线时可用。

### 4.6 日常关怀

- 久坐、长时间盯屏幕、该喝水、深夜还没睡、到点该吃饭。
- 每项单独开关和设置间隔；默认温和、低频。
- 与活动感知联动：玩游戏、看视频、开会、全屏时自动推迟。

## 5. 主动行为的总调度

所有主动说话（播报、活动评论、关怀、随机事件、补提醒）都经过同一个调度器，统一处理：
- 优先级：用户设定的提醒 > 关怀 > 播报 > 活动评论 > 随机事件
- 全局冷却：两次主动发言之间有最短间隔（可设置）
- 勿扰模式、全屏、安静时段、隐私名单下一律不主动说话（用户设定的提醒除外，但全屏时改为稍后提示或系统通知）
- 每日主动调用预算
- 用户连续忽略几次主动发言后，自动降低频率

## 6. 记忆系统的调整

在 v1 记忆系统基础上：

- v1 中关于不可信来源、敏感信息过滤、备份、迁移的规则继续有效。

## 8. 轻量与性能要求

- 体积目标不变：安装包 < 15 MB（不含用户图片）。新增的数据（节假日数据、词库、台词池）要控制体积，如有大文件说明理由。
- 活动感知用系统事件，空闲 CPU 仍接近 0%。
- 动画在角色不可见、窗口被遮挡或全屏时暂停。
- 每个里程碑结束时实测体积、空闲内存、空闲 CPU、启动时间，记录到 PROGRESS，与 V1_AUDIT 中的数值对比，不能明显变差。

### 测试与额度
- 自动测试一律用 mock 后端和假数据（假天气、假时间、假前台窗口），不调用真实 API。
- 时间相关功能（提醒、播报、关怀、冷却）必须能注入假时钟进行测试。
- 真实接口的冒烟测试只在对应接口代码改动后进行，每个接口发一条极短请求，限制输出长度；Key 从系统凭据读取。

- **P0 审计与降级**：V1_AUDIT、文档更新、agent 功能降级为能力层并按需加载、主动行为调度器骨架、每日预算。

每个里程碑结束时可以根据实际情况调整后续计划，原因写进 DECISIONS。
