# v1 审计（方向调整前的状态）

> 2026-10-28 写，依据 `docs/briefs/DIRECTION_V2.md` 第 0 节。v1 = 0.1.6（提交 660f9d3）。
> 目的：弄清 v1 哪些继续用、哪些降级、哪些改造，并留下性能基线，供 v2 每个里程碑对比（不能明显变差）。

## 1. 实测基线（release 0.1.6）

测量方法：`scripts/measure.ps1`（隔离的测试数据目录、mock 后端、空闲 30 秒），本机 Windows 11、用户的 DeskMate 同时在运行。

| 指标 | 实测 | v1 目标 |
|---|---|---|
| 安装包（NSIS） | 3,098,444 字节 ≈ **2.95 MiB** | < 15 MB |
| 主程序 deskmate.exe | 10.0 MiB（未压缩） | — |
| 冷启动到桌宠窗口出现 | **0.57 ~ 0.77 秒**（两次） | < 2 秒 |
| 空闲 CPU（全部进程，占整机） | **0.026 ~ 0.044%**（单核 0.5 ~ 0.9%，基本都是 WebView2 自身） | ≈ 0% |
| 空闲私有内存（全部进程） | **117.5 ~ 119.5 MB**（工作集 359.5 MB，7 个进程） | 越小越好 |
| 前端产物 | 公共运行时 32.8 KB、聊天 15.1 KB、设置 34.0 KB、桌宠 1.9 KB（JS，未压缩） | — |
| 内置角色包 | 8 个，共约 63 KB | — |
| 代码量 | Rust 约 1.52 万行（含测试）、前端约 0.49 万行（含样式和测试） | — |
| 测试 | Rust 185 个（+1 个默认忽略的体检测试）、前端 42 个，全部通过 | — |

各进程私有内存：deskmate 主进程 7.5 MB、WebView2 浏览器进程 44 MB、渲染进程 28~31 MB、GPU 进程 13.5 MB（已关显卡加速）、两个 utility 共 20 MB、crashpad 3.3 MB。
可见 DeskMate 自身很轻，内存主要是 WebView2 的固定开销；v2 新增功能只要不常驻动画、不多开窗口，内存基本不会变。

## 2. 模块清单与处理

### 2.1 继续用（基本不动或只扩展）
| 模块 | v2 里的用法 |
|---|---|
| `desktop.rs` `geometry.rs`（窗口、吸附、托盘、右键菜单） | 继续用；菜单去掉「干活」相关入口，加「提醒」「小游戏」等 |
| `character.rs` `canon.rs` `quotes.rs`（角色包，只读） | 继续用；角色包扩展 `lines/` 台词池、心情表情、亲密度阶段、日记风格、游戏性格 |
| `chat.rs` `prompt.rs` `filter.rs`（对话编排、提示词、禁词） | 继续用；提示词去掉「我能帮你干活」的自我定位，加心情 / 亲密度 / 当前活动等少量背景 |
| `backends/*`（mock / DeepSeek / Gemini / Claude API / Claude 订阅） | 继续用（「模型后端」是必须可扩展的两处之一）；P7 再加图片输入 |
| `memory/*`（短期、摘要、长期事实、FTS5、敏感过滤、备份、维护、导入导出） | 继续用；新增日记类型、活动日志、事件记录、特殊日期 |
| `usage.rs`（用量、花费上限） | 继续用；主动行为单独计数，有自己的每日次数和花费上限，先于聊天被限制 |
| `secrets.rs` `redact.rs` `logging.rs` `paths.rs` `db.rs` `settings.rs` | 继续用；数据库按迁移机制追加新表 |
| `worker.rs`（每 5 分钟：备份、整理记忆、每日维护） | 继续用；加每日日记 |
| `daily.rs` 中的开机自启、快捷键、全屏隐藏、睡觉 | 继续用 |
| 前端 `pet/` `chat/` `settings/` | 继续用；桌宠加触摸反应、聊天窗口加动作按钮和小游戏面板、设置加新页面 |

### 2.2 降级（保留为「高级」选项，默认关闭）
| 模块 | 处理 |
|---|---|
| `tasks/*` `task_cmds.rs` `task_marker.rs`（委托 Claude Code / Codex） | 默认关闭：高级设置里开启「允许委托外部 agent」后才在提示词里出现 `[[任务：…]]` 规则、才会弹任务卡片。安全限制（工作目录、危险操作逐条批准、超时、花费上限、任务日志）一条不动 |
| `TaskCard.tsx`（聊天窗口的任务卡片）、聊天窗口标题栏的 🛠 按钮 | 去掉 🛠 入口；卡片改为按需加载（动态 import），没开委托时根本不加载 |
| `TasksPage.tsx`（设置「任务执行」页） | 移到「高级」页里，改为按需加载 |
| 基本规则里「用户想让你动手做事时……」「看不到实时信息就主动问要不要交给执行工具去查」 | 改为：重度任务（写代码、改代码）用角色口吻建议直接用 Claude Code / Codex；只有开了委托才提议任务 |

降级模块在 Rust 侧本来就是按需运行（只有用户开始任务时才启动进程），启动时只建一个空的状态结构，没有额外开销；前端改成动态加载后，聊天窗口启动时少解析一部分脚本。

### 2.3 改造
| 模块 | 改造成 |
|---|---|
| `daily.rs` 的「主动搭话」 | 并入新的**主动行为调度器**：所有主动说话（提醒、关怀、播报、活动评论、随机事件）统一经过优先级、全局冷却、勿扰 / 全屏 / 安静时段 / 隐私名单、每日预算、被忽略后降频 |
| 任务执行的「打开 / 读取」部分 | 抽出轻量的**内置能力层**：打开文件夹 / 文件 / 网址（打开前在气泡里说明并让用户点一下）、在用户指定的文件夹里读文本文件、查询系统信息（时间、电量、前台程序分类）。优先于外部 agent |
| 角色固定台词 `character.json` 的 `lines` | 保留（出错、断网、额度等），日常场景改用新的 `lines/` 台词池 |

### 2.4 删除
暂不删除任何代码：降级的部分仍作为高级选项可用。以后确认不再使用时，先在 DECISIONS 里记录再删。

## 3. v1 已知遗留问题（带进 v2）
- 「说话」动画两次实测单核 12% 和 1%，原因未查清（只在回复的几秒钟里运行）。v2 要求「角色不可见、被遮挡、全屏时暂停动画」，P8 一并处理。
- 主动说话后没人理会时气泡一直开着 → v2 调度器的「被忽略」处理一并解决。
- 真实 CLI 任务、订阅聊天未在本机实测（按规定不花用户额度）。
- 天气等实时信息只能靠任务流程（DECISIONS #32）→ v2 P2 每日播报内置天气，一并解决「问天气」。
